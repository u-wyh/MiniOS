## ✅ Task3：GDT 与保护模式

### 什么是 GDT

GDT = CPU 在保护模式下“解释内存地址”的规则表
GDT（Global Descriptor Table，全局描述符表）用于定义 x86 保护模式下的段描述符，
CPU 通过段寄存器（CS/DS/SS 等）选择对应描述符，从而确定段基址、界限和访问权限。

### 本轮实现内容

- 在 `boot.asm` 中新增最小 GDT：
  - null descriptor
  - code segment descriptor
  - data segment descriptor
- 新增 GDTR 描述符并执行 `lgdt`
- 使用 far jump 刷新 `CS`
- 重新加载 `DS/ES/FS/GS/SS`

### 修改文件

- 修改：`boot/boot.asm`
- 修改：`readme.md`

### 技术点

- `lgdt`：加载我们定义的 GDT 到 GDTR
- far jump：刷新代码段寄存器 `CS`，使其指向新代码段
- 段寄存器重载：保证数据访问和栈访问进入统一段模型

### 当前系统能力提升

- 内核启动后不再仅依赖加载器默认段环境
- 已显式建立并启用最小受控段模型，为后续 IDT/中断等功能打基础

### GDT 描述符结构（8 字节）

```text
63                     32 31                    0
+----------------------+------------------------+
| Base 31..24 | Flags  | Limit 19..16 | Access  |
+----------------------+------------------------+
| Base 23..16          | Base 15..0             |
+----------------------+------------------------+
| Limit 15..0                                   |
+-----------------------------------------------+
```

说明：
- `Base`：段基址
- `Limit`：段界限
- `Access`：段类型与权限位
- `Flags`：粒度（G）、默认操作数大小（D/B）等控制位

### 段选择子（Selector）结构（16 位）

```text
15                           3 2   1 0
+-----------------------------+---+---+
|         Index               |TI |RPL|
+-----------------------------+---+---+
```

说明：
- `Index`：GDT/LDT 中描述符索引（第几项）
- `TI`：表指示位，`0=GDT`，`1=LDT`
- `RPL`：请求特权级（0~3）

示例：
- `0x08`：`Index=1, TI=0, RPL=0`（代码段选择子）
- `0x10`：`Index=2, TI=0, RPL=0`（数据段选择子）

### 段寄存器要点（保护模式）

常见段寄存器：
- `CS`：代码段寄存器，决定取指所用段
- `DS`：默认数据段寄存器
- `SS`：栈段寄存器（`ESP/EBP` 相关访问）
- `ES`：额外数据段寄存器
- `FS`、`GS`：附加数据段寄存器（常用于线程本地或特定用途）

本轮启动代码中的关键关系：
- 先 `lgdt`：加载我们定义的 GDT
- 再 far jump：刷新 `CS`，让代码段切到新描述符
- 再重载 `DS/ES/SS/FS/GS`：让数据与栈访问统一到新数据段

注意：
- 不能直接 `mov cs, ...`，所以必须用 far jump/retf 等方式更新 `CS`
- 若 `SS` 与栈访问段不一致，可能导致栈读写异常

# MiniOS Phase2：分段机制（Segmentation）总结

---

## 一、分段机制是什么

分段（Segmentation）是 x86 架构在保护模式下提供的一种**内存访问规则系统**。

它的核心思想是：

> 将内存划分为若干“段”，每个段由一条规则描述，CPU访问内存时必须遵循这些规则。

---

## 二、核心组成

### 1. GDT（Global Descriptor Table）

GDT 是一张表（数组），每一项描述一个“段”。

每个段描述符包含：

* base：段起始地址
* limit：段大小（范围）
* 权限：读 / 写 / 执行 / 特权级

👉 本质：

> GDT = “内存访问规则表”

---

### 2. 段寄存器（Segment Registers）

x86 提供 6 个段寄存器：

| 寄存器      | 用途    |
| -------- | ----- |
| CS       | 代码段   |
| DS       | 数据段   |
| SS       | 栈段    |
| ES/FS/GS | 扩展数据段 |

👉 本质：

> 段寄存器 = 当前正在使用的段

---

### 3. 选择子（Selector）

段寄存器中存储的不是地址，而是“选择子”。

选择子用于：

> 指向 GDT 中的某一项

结构（16 位）：

```text
15          3 2   1 0
+------------+-----+
| index      | TI  | RPL |
+------------+-----+
```

* index：GDT 下标
* TI：选择 GDT 或 LDT
* RPL：权限级

---

## 三、地址转换过程（必须掌握）

CPU 访问内存时：

```text
逻辑地址 = selector : offset
```

执行流程：

1. 从段寄存器获取 selector
2. selector → 查 GDT → 获取段描述符
3. 取出 base / limit / 权限
4. 检查 offset 是否越界
5. 计算线性地址：

```text
线性地址 = base + offset
```

---

## 四、段的本质理解

### ❗ 段 ≠ 内存块

段是“访问规则”，不是物理内存本身。

---

### ✔ 一个段：

* 必须是连续内存
* 有独立权限
* 有访问范围

---

### ✔ 多个段：

* 可以完全不连续
* 可以映射到同一块内存（如 flat model）

---

## 五、分段实现的功能

### 1. 内存隔离

不同进程使用不同 base：

```text
进程A → base = 0x00000000
进程B → base = 0x10000000
```

👉 同样 offset → 不同物理地址

---

### 2. 越界保护

```text
offset > limit → CPU 异常
```

---

### 3. 权限控制

* 代码段：可执行，不可写
* 数据段：可读写，不可执行
* ring0 / ring3 权限隔离

---

## 六、平坦模型（Flat Model）

现代操作系统常用：

```text
base = 0
limit = 4GB
```

👉 效果：

```text
线性地址 = offset
```

👉 特点：

* 所有段映射同一内存
* 分段仅保留权限功能
* 简化内存模型

---

## 七、分段的局限性

### ❌ 必须连续内存

容易产生内存碎片

---

### ❌ 管理复杂

段数量有限（最多约 8192）

---

### ❌ 不适合动态分配

扩展困难

---

## 八、为什么被分页替代

分页（Paging）提供：

* 非连续内存映射
* 更灵活的内存管理
* 更高效的共享机制

👉 现代 OS：

```text
分段 → 几乎关闭（flat model）
分页 → 核心机制
```

---

## 九、关键总结

1. GDT 是规则表
2. 段寄存器存 selector
3. selector 指向 GDT 项
4. 地址计算：

```text
物理地址 = base + offset
```

5. 分段提供：

* 内存隔离
* 权限控制
* 越界保护
