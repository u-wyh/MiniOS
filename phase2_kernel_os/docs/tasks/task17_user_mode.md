# Task17：用户态（Ring3）+ 系统调用基础

## 1. 本任务目标

本轮不是实现完整进程系统，而是先把最小特权级切换链路打通：

- 内核从 Ring0 主动切到 Ring3
- 用户态执行一段最小代码
- 用户态通过 `int 0x80` 回到内核

这样就验证了：

- 特权级切换可用
- TSS 内核栈切换可用
- 最小系统调用入口可用

## 2. 核心知识点

### 2.1 什么是 Ring0 / Ring3

在 x86 保护模式里，CPU 有不同特权级：

- `Ring0`：最高权限，通常给内核
- `Ring3`：最低权限，通常给用户程序

内核可以执行所有特权指令，而用户态代码会受到限制。

### 2.2 为什么要用户态

如果所有代码都运行在 Ring0：

- 用户程序出错会直接伤害整个内核
- 很难做权限隔离
- 难以区分“内核资源”和“应用行为”

因此操作系统通常让：

- 内核在 Ring0
- 用户程序在 Ring3

这样用户程序要访问内核服务时，就必须通过系统调用进入内核。

### 2.3 `iret` 为什么能切换特权级

从 Ring0 降到 Ring3 时，不能靠普通 `ret`，而要构造一份特权级返回帧：

1. `user_ss`
2. `user_esp`
3. `eflags`
4. `user_cs`
5. `user_entry`

然后执行 `iretd`。

CPU 会据此：

- 切换 `CS/SS`
- 切换 `EIP/ESP`
- 把当前特权级从 Ring0 变成 Ring3

所以本轮从内核进入用户态的关键，不是普通跳转，而是“伪造一次中断返回”。

### 2.4 系统调用的基本原理

用户态不能直接调用内核内部函数，因此需要一个受控入口。

本轮使用最小方式：

- 用户态执行 `int 0x80`
- CPU 查 `IDT[0x80]`
- 切到内核态中断处理入口
- 内核打印验证信息

这就是最小系统调用雏形。

### 2.5 为什么需要 TSS

当 CPU 从 Ring3 通过中断进入 Ring0 时，不能继续使用用户栈。

它需要知道：

- Ring0 应该切到哪一个栈

这个信息来自 TSS（Task State Segment）里的：

- `esp0`
- `ss0`

因此本轮虽然没有实现真正的硬件任务切换，但仍然需要最小 TSS 来完成“用户态中断进入内核”的栈切换。

## 3. 当前执行流程

当前最小链路如下：

```text
kernel(Ring0)
-> 构造用户态返回帧
-> iretd
-> user(Ring3)
-> int 0x80
-> CPU 使用 TSS 切回内核栈
-> isr80
-> interrupt_handler_80
-> 内核打印信息并停机
```

这条链路验证的是“用户态能够进入内核”，不是完整系统调用返回协议。

## 4. 关键代码解释

### 4.1 GDT 用户段

本轮在 GDT 中新增了：

- 用户代码段（DPL=3）
- 用户数据段（DPL=3）

这样 CPU 才允许在 Ring3 使用对应段选择子。

### 4.2 `enter_user_mode`

这个汇编入口负责：

- 预装用户数据段选择子
- 压入 `SS/ESP/EFLAGS/CS/EIP`
- 执行 `iretd`

它的作用是：把当前执行流从内核安全地降权到用户态。

### 4.3 `interrupt_handler_80`

这是内核态系统调用处理入口。

本轮只做一件事：

- 打印 `syscall entered kernel from Ring3`

然后停机。

这样可以保证验证结果足够清楚，不会和调度器、键盘、Shell 混在一起。

### 4.4 用户页访问权限

因为用户态要执行高地址别名代码、也要使用自己的用户栈，所以相关页表项需要设置：

- `Present`
- `RW`
- `User`

否则 Ring3 虽然拿到了 `CS/SS`，但一访问页面仍会触发页故障。

## 5. 常见错误

### 5.1 没有用户段（DPL=3）

如果 GDT 里没有用户代码段 / 用户数据段，`iretd` 进入 Ring3 时会直接失败。

### 5.2 没有 TSS

如果没有 `esp0/ss0`，用户态 `int 0x80` 进入内核时，CPU 不知道该切到哪个内核栈，通常会直接崩。

### 5.3 `IDT[0x80]` 没有放开 DPL=3

如果 `int 0x80` 的门描述符仍是 DPL=0，Ring3 触发它会得到权限异常。

### 5.4 用户页没有设置 User 位

即使段切换成功，只要用户态访问的代码页或栈页仍是 supervisor-only，也会立刻 page fault。

### 5.5 把 `ret` 和 `iretd` 混用

本轮从 Ring0 降到 Ring3，必须依赖 `iretd` 恢复完整特权级返回现场，普通 `ret` 做不到这件事。

## 6. 一句话总结

Task17 打通了 MiniOS 的最小特权级切换链路：内核可通过 `iretd` 进入 Ring3，用户态可通过 `int 0x80` 回到内核。
