# Task13：物理内存管理（页分配器）

## 1. 什么是物理内存管理

物理内存管理负责回答一个最基础的问题：

- 现在哪些物理内存块还能用
- 需要内存时该分给谁
- 用完后怎样归还

本轮只做最小模型，不涉及分页、虚拟地址或复杂堆分配。

## 2. 为什么按“页”管理（4KB）

页是操作系统里最常见的内存管理粒度。x86 体系里 4KB 是最经典、最基础的一页大小。

按页管理的好处是：

- 粒度固定，逻辑简单
- 地址计算方便
- 后续接入分页机制时模型自然衔接

## 3. 什么是 bitmap 分配器

bitmap 分配器就是用一个数组记录每一页的状态：

- `0`：空闲
- `1`：已分配

当需要分配页时，就遍历 bitmap，找到第一个空闲槽位，把它标成已分配，再把对应页地址返回出去。

这种方式的优点是：

- 实现简单
- 适合当前阶段教学和验证

## 4. 为什么从 1MB 开始分配

本轮把物理页分配起点设在 `0x100000`，也就是 1MB。

这么做是因为：

- 低地址区域常常保留给传统实模式历史区域
- 早期内核和启动相关数据也常在低地址附近
- 从 1MB 往后分配，更容易避开最前面的特殊区域

## 5. 执行流程

```text
shell -> alloc -> mm -> bitmap -> 返回页地址
```

更具体地说：

1. 用户在 shell 输入 `alloc`
2. `shell_execute()` 调用 `alloc_page()`
3. `alloc_page()` 扫描 bitmap
4. 找到空闲页后标记为已分配
5. 根据页下标计算地址并返回

释放时则相反：

```text
shell -> free -> mm -> 根据地址反推页下标 -> bitmap 置 0
```

## 6. 常见错误

- 地址计算错误：页号和地址之间换算出错
- bitmap 越界：扫描或释放时超出有效页数范围
- free 错误页：传入了不在管理范围内的地址
- bitmap 未初始化：会让页状态从一开始就是脏的

## 7. 一句话总结

物理内存管理的本质是“用数据结构管理可用空间”。
