# Task16：高地址内核

## 1. 为什么要高地址内核

高地址内核的核心想法是：

- 把内核放到地址空间高端
- 低地址更多留给用户空间或其他用途

这样做的价值在于：

- 内核和低地址区域更容易区分
- 后续做用户空间 / 内核空间划分时更自然

## 2. 用户空间 / 内核空间划分

在 32 位常见布局里：

- 低地址通常更适合留给用户空间
- 高地址通常留给内核

本轮选择的内核高地址基址是：

- `0xC0000000`

这意味着页目录第 768 项开始对应内核高地址窗口。

## 3. 页目录映射关系

当前最小实现同时保留两种映射：

- `PDE[0]`：低地址 identity mapping
- `PDE[1]`：继续覆盖 4MB~8MB 的低地址区域
- `PDE[768]`：把 `0xC0000000` 起始的 4MB 高地址窗口映射到前 4MB 物理内存

这样做的原因是：

- 开启分页瞬间，CPU 仍在低地址继续执行
- 如果没有低地址 identity mapping，系统会立刻崩溃
- 但只保留低地址又无法体现高地址内核，所以还要额外建立高地址别名

## 4. 跳转流程

当前流程是：

1. 先在低地址环境初始化页目录/页表
2. 打开分页
3. 根据当前函数地址计算出它对应的高地址别名
4. 通过函数指针跳到高地址别名继续执行

可以概括为：

```text
低地址启动 -> 开启分页 -> 跳到 0xC0000000 以上别名 -> 继续执行内核初始化
```

## 5. 本轮实现特点

本轮是“最小高地址映射基础”，并不是完整 higher half 链接布局。它的重点是：

- 让执行流能够进入高地址别名
- 保持现有系统稳定，不立刻崩溃

所以它仍然保留了低地址 identity mapping，便于平滑切换。

## 6. 物理地址与虚拟地址的关系

本轮最容易混淆的一点是：

- 改变的是虚拟地址
- 没有主动搬动物理内存里的内核代码

例如：

- 内核代码物理上仍然可能位于 `0x00100000` 附近
- 但开启分页后，CPU 可以通过页表把它看作 `0xC0100000` 一类高地址

也就是说：

- 物理地址没有变
- 虚拟地址视图变了

这就是高地址内核的核心：不是把代码真的搬到高处，而是让内核在地址空间中“看起来位于高地址”。

## 7. 为什么分页会涉及 4GB 虚拟地址空间

在 32 位体系下，一个地址是 32 位，因此单个地址空间最多可表示：

- `2^32 = 4GB`

这里的 4GB 指的是：

- 一个进程理论上可见的虚拟地址空间上限

并不是说：

- 整个系统所有进程总共只有 4GB 地址可用
- 或者每个进程都会真的占满 4GB 物理内存

更准确地说：

- 每个进程都可以拥有自己的一套 4GB 虚拟地址空间视图
- 但其中绝大多数地址通常根本没有映射实际物理页

因此：

- 虚拟地址空间很大
- 真实占用的物理内存可以很小

分页机制的意义，就是把“进程看到的虚拟地址”翻译成“真正访问的物理地址”。

## 8. 为什么高地址内核有意义

把内核映射到高地址后，后续更容易做出清晰的地址空间划分，例如：

- 低地址留给用户程序
- 高地址留给内核

这样做有几个直接好处：

- 内核和用户空间边界更清晰
- 以后做权限隔离更自然
- 多进程时更容易让不同进程共享同一份高地址内核映射

本轮虽然还没有进入真正的用户态和多进程，但已经把这个地址空间骨架搭起来了。

## 9. 一句话总结

高地址内核实现了“把内核放进高地址空间”的第一步，也为后续地址空间隔离打下基础。
