# Task14：内核内存分配器

## 1. 为什么 page 不够用

页分配器一次最小分配单位是 4KB。如果只是想要几十字节的小对象，也直接拿整页，会浪费大量内存。

所以页分配器适合：

- 管理大块、固定页大小的物理内存

但如果内核里只是要一个小结构体、一个链表节点、一个小缓冲区，就需要更细粒度的分配方式。

## 2. kmalloc 的作用

`kmalloc` 的目标就是：

- 给内核提供比 4KB 更小的内存块

在本轮最小实现里，`kmalloc` 不直接做复杂算法，而是：

- 先通过 `alloc_page()` 拿到一整页
- 再把这一页切成固定大小的小块
- 最后从空闲块链表中取一个块返回

这里还有一个关键前提：

- 页分配器不能把“内核自己正在使用的页”再拿出来切块

所以当前实现会从“内核镜像结束地址向上按页对齐后的下一页”开始分配。

## 3. free list 机制

本轮使用最简单的 free list：

- 每个空闲块头部都有一个 `next`
- 所有空闲块通过单链表串起来

`kmalloc` 时：

- 从链表头取一个块

`kfree` 时：

- 把块重新挂回链表头

这样实现很简单，也足够验证“小块分配 / 回收 / 复用”的基本链路。

## 4. 执行流程

```text
shell -> kmalloc -> free_list
                 -> 如果 free_list 为空，则 alloc_page
                 -> 切分页成多个 block
                 -> 返回一个 block 地址
```

释放路径则是：

```text
shell -> kfree -> block 回挂 free_list
```

## 5. 本轮限制

当前实现是故意收敛的最小版本：

- 不支持复杂大小分类
- 不支持 slab
- 不支持 buddy
- 当前固定按 32B 小块分配
- `kmalloc(size)` 只接受不超过 32B 的请求

## 6. 常见错误

- 忘记在 free list 为空时补充新页
- 切分页时块大小或步长算错
- `kfree` 后没把块重新挂回链表
- 超过固定块大小仍然强行分配，导致越界使用

## 7. 一句话总结

`kmalloc` 的本质是：在页分配器之上，再做一层更细粒度的小块管理。
