# Task18：用户空间与分页完善

## 1. 本任务目标

本轮不是简单重复“进入 Ring3”，而是把用户态运行所需的地址空间基础补完整：

- 用户代码区
- 用户栈区
- 用户页映射
- 用户页权限

这样用户态代码不再只是“碰巧能跑”，而是在明确规划过的用户空间布局中运行。

## 2. 核心知识点

### 2.1 什么是用户空间

用户空间是专门留给用户程序使用的虚拟地址区域。

特点：

- 权限较低（Ring3）
- 不能直接执行特权操作
- 访问范围应受分页和权限位限制

### 2.2 什么是内核空间

内核空间是内核使用的地址区域，通常权限更高（Ring0）。

本项目当前采用高地址内核思路：

- `0xC0000000` 以上用于内核高地址映射

这部分地址不应给用户态访问权限。

### 2.3 为什么需要用户栈

即使用户程序只有几条指令，只要它执行中断、调用函数或未来使用局部变量，就需要一块独立栈空间。

如果没有用户栈：

- `iret` 切到 Ring3 后可能立刻崩溃
- `int 0x80` 压用户态返回现场时也会出问题

### 2.4 为什么用户页需要 `PAGE_USER`

分页权限不仅看段权限，也看页表里的 U/S 位。

如果某个页没有 `PAGE_USER`：

- Ring0 可以访问
- Ring3 访问会触发权限异常

因此：

- 用户代码页必须带 `PAGE_USER`
- 用户栈页也必须带 `PAGE_USER`

### 2.5 为什么内核高地址不能给 `PAGE_USER`

如果把 `0xC0000000` 以上的内核映射也开放给用户态：

- 用户程序就可能直接访问内核地址
- 用户空间 / 内核空间的隔离就失效了

所以本轮明确保持：

- 用户页带 `PAGE_USER`
- 内核高地址页不带 `PAGE_USER`

### 2.6 `int 0x80` 为什么需要 DPL=3

用户态执行 `int 0x80` 时，CPU 会先检查 IDT 里对应门描述符的权限。

如果 DPL 不是 3：

- Ring3 没资格触发这个门
- 会直接得到权限异常

所以本轮保留：

- `IDT[0x80]` 使用允许用户态调用的中断门属性

## 3. 地址空间布局

当前用户空间最小布局如下：

- `USER_CODE_VA  = 0x00400000`
- `USER_STACK_TOP = 0x00800000`
- `USER_STACK_SIZE = 4096`
- `KERNEL_BASE = 0xC0000000`

含义：

- 用户代码页映射在 `0x00400000`
- 用户栈页映射在 `0x007FF000 ~ 0x007FFFFF`
- 内核高地址从 `0xC0000000` 开始

可以粗略理解为：

- 低地址一部分留给用户空间实验
- 高地址留给内核

## 4. 执行流程

本轮触发链路如下：

```text
shell 输入 user
-> user_request_enter
-> 内核主循环发现待执行请求
-> user_space_init
-> 建立用户代码页和用户栈页
-> iretd 进入 Ring3
-> 用户代码执行
-> int 0x80
-> 内核 syscall handler
```

本轮选择通过 shell 命令触发，是为了避免在键盘中断上下文里直接做特权级切换。

## 5. 关键代码解释

### 5.1 `map_page`

`map_page(va, pa, flags)` 的作用是：

- 按虚拟地址定位 PDE/PTE
- 必要时分配新的页表页
- 建立 `VA -> PA` 映射

它是本轮“把用户页明确放到指定虚拟地址”的基础。

### 5.2 `user_space_init`

职责：

- 分配一页用户代码页
- 分配一页用户栈页
- 把用户代码页映射到 `USER_CODE_VA`
- 把用户栈页映射到 `USER_STACK_TOP - 4096`

当前用户程序仍然是内核内置测试机器码，不是 ELF 加载结果。

### 5.3 `enter_user_mode`

这个汇编入口负责：

- 压入用户态 `SS / ESP / EFLAGS / CS / EIP`
- 执行 `iretd`

从而把 CPU 从 Ring0 切到 Ring3。

### 5.4 `IDT[0x80] DPL=3`

这是用户态能够合法执行 `int 0x80` 的前提。

如果少了它，Ring3 代码根本进不了系统调用入口。

### 5.5 用户栈构造

本轮没有做复杂用户栈内容初始化，只需要：

- 给用户态一块存在且可写的页
- 把初始 `ESP` 指向 `USER_STACK_TOP`

这样用户态执行中断时，CPU 才能先把用户态返回现场压到合法的栈上。

## 6. 当前限制

当前仍然有这些限制：

- 还没有 ELF loader
- 还没有真正的进程地址空间
- 还没有 page fault handler
- 还没有完整 syscall 表
- 当前用户程序仍然是内核内置测试代码

所以本轮重点是“用户空间结构正确”，不是“完整用户程序运行环境”。

## 7. 常见错误

### 7.1 用户页没 `PAGE_USER`

结果：

- Ring3 访问代码页或栈页时直接权限异常

### 7.2 用户栈没映射

结果：

- `iret` 进入用户态后，一旦用栈就崩

### 7.3 `int 0x80` DPL 不对

结果：

- 用户态无法触发系统调用门

### 7.4 内核页误设 `PAGE_USER`

结果：

- 用户空间 / 内核空间隔离失效

### 7.5 `USER_CODE_VA` 未映射

结果：

- 一进入用户态就 page fault，严重时会 triple fault

## 8. 一句话总结

用户空间的本质是：用分页和权限位限制用户代码能访问的地址范围。
