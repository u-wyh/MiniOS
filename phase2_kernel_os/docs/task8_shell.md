# Task8：Mini Shell 命令解析与执行框架

## 1. 本任务目标

本轮将“输入字符串”升级为“命令执行”，让 MiniOS 在接收到一整行输入后，能够判断命令类型并执行对应功能。

## 2. 核心知识点

- 什么是 Shell：Shell 是用户与操作系统内核交互的最小命令入口
- Shell 在 OS 中的位置：它位于“输入”与“内核功能”之间，负责把用户输入转换成具体操作
- 字符串输入和命令解析的区别：字符串输入只负责接收一行文本，命令解析还要判断“这行文本代表什么功能”
- 命令分发是什么：根据输入内容选择执行不同分支，例如 `help`、`clear`、`echo`
- 为什么裸机环境不能直接用 `strcmp / printf`：当前内核是 freestanding 环境，没有标准 C 库可直接链接
- `help / clear / echo` 分别验证了什么能力：
  - `help`：验证命令匹配与多行输出
  - `clear`：验证命令可调用内核显示功能
  - `echo`：验证最小参数解析与文本输出

## 3. 执行流程

键盘输入 ->
`input_buffer` ->
Enter ->
`shell_execute` ->
命令判断 ->
执行对应函数 ->
重新打印提示符

## 4. 关键代码解释

- `shell_init`：启动时打印首个 `MiniOS> ` 提示符
- `shell_execute`：接收一整行输入，判断是 `help`、`clear`、`echo` 还是未知命令
- `str_equal`：最小字符串全等比较，用来匹配 `help` 和 `clear`
- `str_starts_with`：判断是否以 `echo ` 开头，用来识别带参数命令
- `keyboard_handler` 中调用 `shell_execute` 的变化：Enter 不再直接重打印整行，而是把整行交给 Shell 处理

## 5. 当前限制

- 不支持复杂参数
- 不支持管道
- 不支持文件系统
- 不支持历史命令
- 不支持真正进程执行

## 6. 常见错误

- 忘记重新打印提示符
- 使用 libc 字符串函数导致链接失败
- `clear` 后没有重新显示提示符
- `keyboard` 仍然直接回显整行导致重复输出
- PIT 打印太频繁影响 shell 观察

## 7. 一句话总结

Mini Shell 让 MiniOS 从“能输入字符串”升级为“能理解命令”。
