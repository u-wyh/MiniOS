# Task15：分页机制

## 1. 什么是分页

分页是一套地址翻译系统。CPU 在开启分页后，不再把程序里使用的地址直接当成最终物理地址，而是先经过页目录和页表查找，最后得到真正访问的物理地址。

## 2. 页目录 / 页表

在 32 位两级分页里：

- 页目录（Page Directory）保存 PDE
- 页表（Page Table）保存 PTE

每个表都有 1024 项，每项对应一段地址范围。当前阶段我们只建立最小数量的页表，够内核启动和继续运行即可。

## 3. 虚拟地址如何转换

CPU 访问一个虚拟地址时，会把它拆成几部分：

- 高 10 位：页目录索引
- 中间 10 位：页表索引
- 低 12 位：页内偏移

然后按下面的顺序找到目标物理地址：

```text
VA -> PDE -> PTE -> PA
```

## 4. 为什么先 identity mapping

identity mapping 的意思是：

- 虚拟地址 = 物理地址

例如：

- `0x00100000` 映射到 `0x00100000`

这是开启分页最稳妥的第一步，因为：

- 当前内核代码本来就在这些地址上运行
- 开启分页后如果这些地址没有被映射，CPU 会立刻访问失败

所以最小分页的第一原则是：

- 先把当前正在使用的区域按原样映射出来

## 5. 执行流程

当前 MiniOS 的最小分页初始化流程是：

1. 用页分配器拿到页目录页
2. 用页分配器拿到页表页
3. 填写页表，建立 identity mapping
4. 把页表地址写进页目录
5. 把页目录地址写入 `CR3`
6. 打开 `CR0.PG`

之后 CPU 就会正式启用分页翻译。

## 6. 本轮实现要点

- 页目录和页表都必须 4KB 对齐
- identity mapping 需要覆盖当前内核代码/数据所在区域
- 为了更稳妥，本轮映射了前 8MB，而不只 4MB
- 当前只做内核单地址空间，不涉及用户态和多进程地址空间
- shell 可通过 `paging` 命令打印分页是否已启用，以及页目录/页表地址

## 7. 一句话总结

分页的本质是“给 CPU 加上一层地址翻译系统”。
