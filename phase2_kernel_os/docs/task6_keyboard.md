# Task6：键盘中断输入

## 1. 本任务目标

本轮让 MiniOS 具备最小键盘输入能力：按下普通字母键后，系统通过键盘中断读取扫描码，并将对应字符显示到 VGA 屏幕上。

## 2. 核心知识点

- 键盘中断：键盘按键事件不是轮询获得的，而是由硬件主动发出中断请求通知 CPU
- IRQ1：键盘控制器使用的标准硬件中断号是 `IRQ1`
- 为什么 remap 后是 `IDT[0x21]`：主 PIC 被重映射到 `0x20~0x27`，因此 `IRQ1` 对应 `0x21`
- 端口 `0x60` 的作用：键盘控制器会把最新扫描码放在该数据端口，处理函数必须读取它
- 扫描码 scancode：键盘并不是直接发字符，而是发“哪个键被按下/释放”的编码
- 扫描码不是 ASCII：比如按下 `a` 键，硬件先给出的是扫描码 `0x1E`，需要软件再把它映射成字符 `'a'`
- 扫描码集合：不同键盘/模式会有不同扫描码集合（scan code set），本轮使用最常见的 Set 1
- 按下码和释放码：本轮使用 Set 1 扫描码，释放码的最高位通常为 `1`，因此可以用 `scancode & 0x80` 判断并忽略
- 为什么需要 EOI：如果键盘中断处理完不向 PIC 发送 EOI，PIC 可能不再转发后续键盘中断

### 扫描码的最小理解

可以把扫描码理解成“键盘发给操作系统的原始按键编号”。

- CPU/内核最先拿到的是扫描码，不是字母本身
- 如果想在屏幕上显示字符，就要做 `scancode -> ASCII` 映射
- 例如本轮代码里：
  - `0x1E -> 'a'`
  - `0x30 -> 'b'`
  - `0x2E -> 'c'`
- 如果以后支持 `Shift`、大写字母、符号键，就不能只靠这张最小映射表，还要结合修饰键状态一起判断

### 当前阶段涉及的硬件 IO 端口

| 端口 | 设备 | 作用 |
| --- | --- | --- |
| `0x20` | 主 PIC 命令端口 | 发送初始化命令、发送主片 EOI |
| `0x21` | 主 PIC 数据端口 | 设置主片中断向量偏移和中断屏蔽位 |
| `0xA0` | 从 PIC 命令端口 | 发送初始化命令、发送从片 EOI |
| `0xA1` | 从 PIC 数据端口 | 设置从片中断向量偏移和中断屏蔽位 |
| `0x43` | PIT 控制端口 | 写入 PIT 控制字，选择通道/模式/读写方式 |
| `0x40` | PIT 通道 0 数据端口 | 写入定时器分频值低字节和高字节 |
| `0x60` | 键盘控制器数据端口 | 读取键盘扫描码 |
| `0x80` | 延时端口 | `io_wait()` 用作极短硬件时序等待 |

这些端口是 CPU 通过 `inb/outb` 与外设通信的入口。当前 MiniOS 已经用到的外设主要就是 PIC、PIT 和键盘控制器。

## 3. 硬件工作流程

键盘按下 -> 键盘控制器 -> PIC -> CPU -> IDT[0x21] -> irq1_stub -> keyboard_handler -> 读取 `0x60` -> 显示字符 -> 发送 EOI

## 4. 执行流程

系统启动后，`kernel_main()` 先初始化 IDT、PIC、PIT，再执行 `sti` 开启外部中断。之后：

- PIT 持续通过 `IRQ0` 周期性打断系统
- 键盘按下时触发 `IRQ1`
- CPU 根据 `IDT[0x21]` 跳到 `irq1_stub`
- `irq1_stub` 保存现场后调用 `keyboard_handler()`
- `keyboard_handler()` 从 `0x60` 读取扫描码，映射成字符并输出

## 5. 关键代码解释

- `irq1_stub`：汇编层入口，负责保存通用寄存器、调用 C 处理函数、恢复寄存器并 `iret`
- `keyboard_handler`：C 层键盘处理逻辑，读取扫描码、过滤释放码、打印字符、发送 EOI
- `scancode_to_ascii`：把最小范围的 Set 1 扫描码转换成 `a-z` 或 `0-9`
- `inb(0x60)`：从键盘控制器数据端口读取本次按键扫描码
- `pic_send_eoi(1)`：通知 PIC 本次 `IRQ1` 已经处理完成

## 6. 常见错误

- 没注册 `IDT[0x21]` -> 键盘无响应
- 没读取 `0x60` -> 键盘控制器状态异常，后续按键可能失常
- 没发送 EOI -> 只响应一次
- 没 `sti` -> 外部中断不触发
- scancode 映射错误 -> 输出字符不对

## 7. 一句话总结

键盘中断让 MiniOS 从“自动运行”进入“可交互运行”。
