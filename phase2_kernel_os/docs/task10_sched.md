# Task10-2：PIT 驱动自动调度

## 1. 本任务目标

让 MiniOS 不再依赖 shell 手动输入 `task` 命令，而是使用 PIT 定时器中断自动触发任务切换，在两个最小任务之间持续轮转执行。

## 2. 核心知识点

### 什么是调度器

调度器负责决定“下一次 CPU 应该运行哪个任务”。在本轮最小实现里，它只做一件事：在任务 A 和任务 B 之间轮流切换。

### 什么是时间片

时间片可以理解为“某个任务连续占用 CPU 的一小段时间”。时间片结束后，调度器就有机会把 CPU 切给另一个任务。

### PIT 如何驱动调度

PIT 会周期性触发 IRQ0。CPU 进入定时器中断后，`timer_handler()` 会更新 `tick_count`，并在满足切换条件时调用 `schedule()`，完成任务轮转。

## 3. 执行流程

```text
PIT -> IRQ0 -> irq0_stub -> timer_handler -> schedule -> 切换 ESP -> popa -> iret -> 新任务继续运行
```

更具体一点：

1. PIT 到点触发一次时钟中断
2. CPU 进入 `irq0_stub`
3. 汇编先保存当前任务寄存器
4. `timer_handler()` 判断当前 tick 是否到达切换边界
5. 若需要切换，则 `schedule()` 保存旧任务 ESP，并返回新任务 ESP
6. 汇编把 `esp` 切到新任务的中断现场
7. `popa + iret` 恢复新任务，CPU 从新任务继续执行

## 4. 为什么不能一直切（频率问题）

如果每一次 PIT 中断都立即切换，而且任务本身又做了大量输出，屏幕会非常混乱，调试也会困难。本轮采用“固定 tick 间隔后再切换”的最小策略，让切换节奏更稳定、行为更容易观察。

## 5. 关键代码解释

### `schedule()`

它是最小 round-robin 调度器。核心逻辑很简单：

- 记录当前任务编号
- 计算下一个任务编号
- 保存旧任务 `esp`
- 返回新任务 `esp`

### `timer_handler()`

它不直接打印任务内容，只做两类事情：

- `tick_count++`
- 在时间片边界调用 `schedule()`

这样可以保证中断处理尽量短小，避免在中断上下文里堆太多复杂逻辑。

### `task_a()` / `task_b()`

两个演示任务只做最小工作：

- 任务 A 输出 `A`
- 任务 B 输出 `B`
- 输出后执行 `hlt` 等待下一次中断

这样既能观察调度效果，也能避免一个任务在自己的时间片里疯狂刷屏。

## 6. 每次中断时是怎样保存现场的

这是本轮最关键的底层动作。所谓“保存现场”，本质上就是把当前任务被打断时的执行状态先压到栈里，这样之后才有机会恢复回来。

### 第一步：CPU 自动保存一部分现场

当 PIT 触发 `IRQ0`，CPU 进入中断时，并不是直接跳到 `irq0_stub` 什么都不做。CPU 会先自动把最核心的返回信息压栈：

- `EIP`
- `CS`
- `EFLAGS`

可以把它理解成：

- `EIP`：中断前执行到了哪条指令
- `CS`：当时使用的是哪个代码段
- `EFLAGS`：当时的标志寄存器状态

这三项信息决定了“以后怎样回到被中断的位置继续执行”。

### 第二步：`irq0_stub` 用 `pusha` 保存通用寄存器

CPU 自动保存的只是一部分最关键的返回信息，但还不够。因为当前任务执行时，`eax`、`ebx`、`ecx` 这些通用寄存器里也可能正放着任务自己的临时数据。

所以 `irq0_stub` 进入后第一件事就是：

```asm
pusha
```

它会把 8 个通用寄存器继续压到当前栈里。这样这个栈上就形成了一个完整得多的“中断现场”。

### 第三步：把当前现场栈顶交给 C 层

在 `pusha` 之后，`esp` 指向的就是“这次中断现场”的栈顶。代码里会把它作为参数传给 `timer_handler()`：

```asm
push esp
call timer_handler
```

这一步的意义是：

- 调度器可以拿到“旧任务现在的栈保存位置”
- 如果要切换任务，就把这个 `esp` 存回旧任务的 `TCB`

也就是说，当前任务的完整现场，其实就躺在它自己的栈里，而 `esp` 就是找到这份现场的入口。

### 第四步：如果需要切换，就改成新任务的 `esp`

`timer_handler()` 内部会决定本次是否切任务。如果要切，它最终返回的是“新任务保存现场所在的栈顶地址”。

回到汇编里：

```asm
mov esp, eax
```

这一步不是“复制数据”，而是直接把 CPU 当前使用的栈切到另一个任务那份现场上。

从这一刻开始，后面的恢复动作就不再针对旧任务，而是针对新任务。

### 第五步：`popa + iret` 恢复新任务现场

切到新任务栈后，汇编继续执行：

```asm
popa
iret
```

含义分别是：

- `popa`：恢复通用寄存器
- `iret`：恢复 `EIP / CS / EFLAGS`

这样 CPU 就能从新任务上次停下的位置继续往下跑。

### 为什么只保存 `esp` 也够用

在 `TCB` 里我们只保存了一个字段：

```c
typedef struct {
    uint32_t esp;
} task_t;
```

这并不是说系统只保存了 `esp`，而是说：

- 真正的寄存器内容已经保存在任务自己的栈里
- `esp` 只是这份完整现场的入口地址

所以当前最小任务系统的核心思路就是：

- 现场数据在栈里
- `TCB` 只记录“这份现场从哪里开始”

## 7. 常见错误

- 栈格式不一致：首次启动任务和中断恢复任务走了不同返回路径，容易直接跳飞
- 忘记保存旧任务 `esp`：下次恢复时拿不到正确现场
- 在中断里做太多事情：会让调度器行为变得不稳定
- 不发送 `EOI`：后续定时器中断会停止
- 任务里不 `hlt`：单个时间片可能刷出大量同字符，难以观察轮转效果

## 8. 一句话总结

调度器的本质是“在中断中切换栈”，而 PIT 给了我们稳定的切换时机。
